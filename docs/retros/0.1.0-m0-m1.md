# Retro — M0 + M1, v0.1.0 (2026-11-12)

**Scope:** everything on `main` from the first commit (2026-11-11) to the adoption of the shipping
guards: M0 (foundation), M1 (data backbone) and the M2 work so far. About 50 commits, pushed straight
to `main`; there was no `VERSION` or `CHANGELOG.md` before this one. The detail lives in
[`HANDOFF.md`](../HANDOFF.md) §3 (lessons) and §4–5 (milestones).

## What went well

- **Tests on saved real responses first.** Every parser and mapper is tested against real Clerk, LIS
  and Congress.gov payloads in `fixtures/`, which is how lessons 9–13 (portion short titles, summary
  ordering, the 20-item page limit, split nominations, military nominations) were caught and pinned.
- **Verification against official totals, not samples.** Every one of 3,532 votes' positions adds up
  to its official totals, and the bill spot-check measured the error rate on the 58 largest bills
  (36% wrong `short_title`) instead of trusting a random 60 that came back clean.
- **A committed contract.** `apps/api/openapi.json` is checked for drift in CI, and the hand-written
  Swift models are checked against it by `ContractTests`, so API and app cannot silently disagree.

## What was hard to understand

- **Where the project stood.** The README said "M1 nearly done · next M2" while `HANDOFF.md` said M2
  was nearly done, and the HANDOFF's own summary paragraph said the app was "still a skeleton" one
  sentence before saying it ran end to end. Each status line was right when written and nothing made
  anyone revisit it.
- **What a change had shipped.** With no version or changelog, "what changed since Tuesday" was a
  read of the commit log.
- **The Swift toolchain.** `swift test` dies with a missing `SWBBuildService.framework` when
  `xcode-select` points at the Command Line Tools — reads like a broken install, is a selection.

## Follow-ups blocked (and why)

- **The ruleset.** Until a repo admin turns it on (Settings → Rules → a ruleset on `main` requiring
  pull requests and the `guards` status check), the guards are advice: they report on every PR but
  stop nothing. Setting squash merges to use the PR title would also let
  `PR_TITLE_CHECK_SUBJECT` in `guards.conf` go back to 0.
- **Posting latency** waits on M3 by construction.
